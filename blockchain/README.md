# VaultChain Registered Original Registry

This module is the local Hyperledger Fabric 2.5 development network and Go
chaincode for anchoring verified originals. It is deliberately isolated from
Spring, the browser, and the AI service.

## Topology

- Channel: `vaultchain-channel`
- `CreatorsOrgMSP`: one peer at `localhost:7051`, backed by CouchDB
- `AuthenticatorsOrgMSP`: one peer at `localhost:9051`, backed by CouchDB
- `OrdererOrgMSP`: one local Raft orderer at `localhost:7050`
- Chaincode: `registered-original-registry`
- Endorsement: `AND('CreatorsOrgMSP.peer','AuthenticatorsOrgMSP.peer')`

The network uses development identities generated by `cryptogen`. It is not a
production trust or certificate-management design.

## Prerequisites

- Docker Engine and Docker Compose v2
- Go 1.20 or newer
- Hyperledger Fabric CLI binaries from one pinned 2.5.x release (`peer`,
  `cryptogen`, and `configtxgen`)
- The matching Fabric CLI `config/core.yaml`, exposed through
  `FABRIC_CFG_PATH`
- Docker images `hyperledger/fabric-peer:2.5.12`,
  `hyperledger/fabric-orderer:2.5.12`,
  `hyperledger/fabric-ccenv:2.5.12`,
  `hyperledger/fabric-baseos:2.5.12`, and `couchdb:3.3.3`

Nothing is downloaded by network startup or application runtime. Acquire the
Fabric 2.5.x binaries and images explicitly from the official Hyperledger
Fabric distribution, put the binaries on `PATH`, and set the CLI configuration
path, for example:

```bash
export PATH="<fabric-distribution>/bin:$PATH"
export FABRIC_CFG_PATH="<fabric-distribution>/config"

docker pull hyperledger/fabric-peer:2.5.12
docker pull hyperledger/fabric-orderer:2.5.12
docker pull hyperledger/fabric-ccenv:2.5.12
docker pull hyperledger/fabric-baseos:2.5.12
docker pull couchdb:3.3.3
```

Prepare vendored Go dependencies explicitly before deployment:

```bash
cd blockchain/chaincode/registry
go mod download
go mod vendor
go test ./...
cd ../..
```

## Start and deploy

From the repository root:

```bash
cd blockchain
./scripts/network-up.sh
./scripts/deploy-registry.sh
```

`network-up.sh` creates development crypto material, starts Docker Compose,
creates `vaultchain-channel`, and joins both peers. `deploy-registry.sh`
requires an existing `chaincode/registry/vendor/` directory and commits the
two-organization endorsement policy.

## Test the registry

The smoke test uses only the fixed fake asset documented below. It calls
`RegisterOriginal`, `GetOriginal`, `FindBySha256`, and `GetAssetHistory`, and
confirms that a second asset cannot claim the same SHA-256.

```bash
./scripts/smoke-test-registry.sh
```

To run the same operations manually after deployment, use the shared CLI
environment helpers:

```bash
source scripts/common.sh
set_creators_peer
orderer_arguments
both_peer_arguments

peer chaincode invoke "${ORDERER_ARGS[@]}" "${BOTH_PEER_ARGS[@]}" \
  --channelID vaultchain-channel \
  --name registered-original-registry \
  --waitForEvent \
  --ctor '{"function":"RegisterOriginal","Args":["11111111-1111-1111-1111-111111111111","creator-test-hash","aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","IMAGE","VERIFIED","bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"]}'

peer chaincode query --channelID vaultchain-channel \
  --name registered-original-registry \
  --ctor '{"function":"GetOriginal","Args":["11111111-1111-1111-1111-111111111111"]}'

peer chaincode query --channelID vaultchain-channel \
  --name registered-original-registry \
  --ctor '{"function":"FindBySha256","Args":["aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"]}'

peer chaincode query --channelID vaultchain-channel \
  --name registered-original-registry \
  --ctor '{"function":"GetAssetHistory","Args":["11111111-1111-1111-1111-111111111111"]}'
```

Fake seed values:

| Field | Value |
|---|---|
| `assetId` | `11111111-1111-1111-1111-111111111111` |
| `creatorIdHash` | `creator-test-hash` |
| `sha256` | `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa` |
| `assetType` | `IMAGE` |
| `verificationStatus` | `VERIFIED` |
| `evidenceHash` | `bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb` |

## Stop and reset

Stop containers and remove their Docker volumes while retaining generated
development identities and channel artifacts:

```bash
./scripts/network-down.sh
```

Reset all generated Fabric material as well:

```bash
./scripts/reset-network.sh
```

## Ledger boundary

On-chain data is limited to the public asset UUID, pseudonymous creator/current
owner references, exact SHA-256, asset type, `VERIFIED` status, evidence-record
hash, transaction timestamp, and Fabric key history. Image/PDF bytes, pHash,
UFD and TruFor results, localization maps, OCR, paths, JWTs, and personal
identity records remain off-chain.

This local MVP intentionally differs from the intended production topology.
Production expands to Creators, Authenticators, Galleries, and Buyers
organizations with three Raft orderers, production certificate authorities,
secure secrets, and operational infrastructure. The current authenticated
Spring Fabric Gateway integration is documented in `../server/README.md`;
public originality verification and production identity authorization remain
separate follow-up work.
